Migrate a database

Copies the tables (columns, primary keys, unique constraints, indexes, foreign keys and checks), their rows, the sequences, views, procedures, functions and triggers to a new database of another type. The source is only read. cactusdb creates the new database and writes only to it: it refuses one that already exists.

    Settings
    
    
    
    
    When nobody clicks, types or scrolls for this long, cactusdb disconnects from the database.
      It never disconnects while something is running (a query, an export, a backup), and counts again from when it
      finishes. 0 means never. The default is 15 minutes. The setting is saved on
      the cactusdb server and applies to everyone using it.
    

    
    Google Analytics
    
    
    Off until a Measurement ID is set, and then still only for the people who say yes in their browser.
      Only which functions are used is sent (tabs, menu items, connect, export…), never data, SQL, names or addresses.
    
    
    
    
    
    
    
    
    
    
    
    Command-line runs are sent by the server itself, so it needs to reach Google and an API secret
      (Admin → Data streams → your stream → Measurement Protocol API secrets). They wait at most 2 seconds for Google.
      They are always recorded in the usage log.

          Folder setup
          
    
          Exports and backups are saved in …, one folder per connection.
          
    
    
    
          A full path, e.g. . It's created if it doesn't exist. Each export type
      goes to its own subfolder (json, csv, xlsx, xml, sql). The folder is saved and used again the next time cactusdb starts.
          
    
          
    
          
    
          
      
      
      
      
    
          
    
          Connection database
          
    
          Saved connections, saved queries, settings and the usage log are kept in ….
          
    
    
    
          A full path of the new file, or of a folder to put cactus.conn.db in, e.g. .
      The folder is created if it doesn't exist; an existing file is never overwritten. The key file (cactus.key) goes along
      when it is next to the database, and the old files are deleted. cactusdb remembers the new place for the next start
      (in cactus.conn.db.location next to the program).
